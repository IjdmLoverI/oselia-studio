# Architecture

One Next.js application serves both the public site and the Payload admin. Payload runs
inside Next and talks to Postgres. There is no separate API server. Pages read content
through Payload's Local API, which is a direct function call inside the same process.

```
browser ──► Next.js (Vercel)
              ├─ (frontend)/[locale]/…   React Server Components ──► Payload Local API ──► Postgres
              ├─ (payload)/admin         Payload admin UI
              ├─ (payload)/api           Payload REST and GraphQL
              └─ submitLead (server action) ──► Leads collection, Telegram Bot API
uploads ──► Vercel Blob (production) or ./media (local)
```

## Routes

| Path                          | Source                                         |
| ----------------------------- | ---------------------------------------------- |
| `/uk`, `/en`                  | `src/app/(frontend)/[locale]/page.tsx`         |
| `/[locale]/projects/[slug]`   | `src/app/(frontend)/[locale]/projects/[slug]`  |
| `/[locale]/credits`           | photo credits, built from the Media collection |
| `/[locale]/opengraph-image`   | per-language social image from `next/og`       |
| `/sitemap.xml`, `/robots.txt` | `src/app/sitemap.ts`, `src/app/robots.ts`      |
| `/admin`, `/api/*`            | generated by Payload, not edited by hand       |

`src/proxy.ts` is the Next 16 replacement for `middleware.ts`. It runs the next-intl
middleware for everything except the admin, the API, Next internals and static files. A
request to `/` is redirected to `/uk` or `/en`, based on the locale cookie or the
`Accept-Language` header.

## Rendering and caching

- **Build time.** The home page, project pages and the credits page are prerendered for both
  languages. `generateStaticParams` asks Payload for the published projects, so the database
  must be reachable during `next build`.
- **New content.** Projects published after a deploy render on their first request and are
  cached after that.
- **Revalidation.** Every content collection and global has `afterChange` / `afterDelete`
  hooks. They call `revalidatePath('/', 'layout')`, which marks every page as stale. An editor
  sees the change on the next page load, with no rebuild. The site is small, so revalidating
  everything is simpler than tracking which page uses which document.
- **Seeding.** The seed passes `context.disableRevalidate`, so the hooks skip revalidation when
  the script runs outside Next.
- **Query caching.** The queries in `src/lib/content.ts` are wrapped in React `cache()`. A page
  and its `generateMetadata` share one database round trip.
- **Hydration.** Below-the-fold sections sit in their own `Suspense` boundaries, so React can
  hydrate them one at a time instead of in a single long task.

## Internationalization

There are two layers:

1. **Interface text.** Buttons, headings and form errors live in `messages/uk.json` and
   `messages/en.json`, loaded by next-intl.
   - `src/global.d.ts` registers the message shape with next-intl, so a missing key is a type
     error.
   - Routing uses `localePrefix: 'always'`, so every URL carries its language. This makes
     caching and `hreflang` unambiguous.
2. **Content.** Text in the CMS uses Payload's field-level localization.
   - Localized fields store a value per language. Numbers, images and relations are shared.
   - English falls back to Ukrainian when a translation is missing.
   - The admin interface itself is available in both languages.

## Lead flow

`ContactForm` posts to the `submitLead` server action (`src/actions/submit-lead.ts`) through
`useActionState`.

1. **Honeypot.** A hidden `company` field must stay empty. Bots that fill it get a fake
   success.
2. **Time trap.** The browser measures the time from the first focus inside the form to the
   submission and sends it as `fillTime`. Anything under 3 seconds is rejected. Both ends of
   the measurement come from the same clock, so a visitor whose device clock is off is never
   refused by mistake.
3. **Validation.** `leadSchema` (zod, `src/lib/lead.ts`) checks the fields.
   - Phone numbers are normalized to `+380…` or another international format.
   - Field errors go back to the form and are tied to their inputs with `aria-invalid` and
     `aria-describedby`. Form-level errors use `role="alert"`.
4. **Rate limit.** The client IP is hashed together with `PAYLOAD_SECRET` and stored on the
   lead. Raw IPs are never stored. More than three leads from one hash in ten minutes are
   refused. The limit uses the leads table itself, so no Redis or third-party service is
   needed.
5. **Storage.** The lead is saved in the `leads` collection. Public create access is closed;
   only this server action writes leads.
6. **Notification.** The lead is sent to Telegram with `sendMessage`.
   - The message is built by `formatLeadMessage`, with HTML escaping.
   - The request has a 5-second timeout.
   - If Telegram is not configured or fails, the lead is still saved and the visitor still sees
     success.

The calculator and the form share state through a small `useSyncExternalStore` store
(`src/lib/estimate-store.ts`). "Get an exact estimate" copies the area, type, extras and price
range into the form.

## Motion

The rule is: CSS where it can be done in CSS, Motion where the animation depends on scroll or
the pointer.

**CSS**

- **Intro.**
  - A boot script in `<head>` marks the first visit in `sessionStorage`. The preloader and the
    long intro play only once per session.
  - Headings reveal word by word through masks.
  - The hero arch opens with a transform-based curtain.
  - On screens narrower than 768 px the preloader is skipped and the intro is shorter.
- **Scroll reveals.** `InView` (Motion's `useInView`) only flips `data-reveal` to `visible` once
  an element enters the viewport. CSS transitions do the animation.
- **Reviews.** The strip loops with a CSS animation and pauses on hover or keyboard focus.
- **FAQ.** The `<details>` elements animate their height through `::details-content` and
  `interpolate-size`.

**Motion for React**

- `Header` hides while scrolling down.
- `Marquee` moves on `useAnimationFrame`. Scroll velocity speeds it up, and scrolling up
  reverses it.
- `SketchToReality` is a pinned section driven by `useScroll`.
- `Cursor` and `MaterialSpheres` follow the pointer through springs.
- `AnimatedNumber` eases the calculator total.

**Lenis** smooths wheel scrolling. Like the cursor and the parallax, it runs only on fine
pointers. Touch devices keep native scrolling.

**Material textures** are SVG noise filters rendered to small WebP files ahead of time
(`npm run materials`). Filtering them live in the browser cost about three seconds of main
thread on a mid-range phone.

**Reduced motion.** `MotionConfig reducedMotion="user"` plus a `prefers-reduced-motion` block
in `globals.css` turn every effect off. Content is fully visible without JavaScript.

**Mood switcher.** It swaps the accent palette (terracotta, olive, graphite) by setting
`data-mood` on `<html>`, wrapped in `document.startViewTransition` where supported. The choice
is kept in `localStorage` and applied by the boot script before first paint.

## Images

- **CMS uploads.** These go through `CmsImage`, a thin wrapper over `next/image`.
  - Payload stores WebP originals plus `thumb`, `card` and `wide` sizes.
  - A `beforeChange` hook stores a 16 px blurred preview as `blurDataURL`, used as the
    placeholder.
- **Static art.** The hero photo, the sketch-to-photo pair and the material textures are
  imported from `src/assets`, so Next can fingerprint them and serve AVIF or WebP.

## Security headers

`next.config.ts` sends `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options` and a
restrictive `Permissions-Policy` on every route. It also removes `X-Powered-By`.
